> *memo-init turns long, unstructured input — typically dictated voice transcripts — into discrete, executable work orders, and governs the human-AI interaction that clarifies open questions before implementation begins.*

memo-init is a memo-driven approach to agentic software engineering. The developer plans; the AI implements autonomously and self-evaluates. The whole process is written down as an RFC-style specification, reverse-engineered from a real, working system.

## Mission

A **memo** is a versioned strategy document. It starts as a first revision, iterates through revisions until the developer finalizes it, and then drives a rollout that produces real artifacts — code, repositories, documentation. The memo is the single highest authority over its own rollout.

The specification is **inductive**: it is reverse-engineered from a real, working system and written in the normative style of an RFC (MUST / SHOULD / MAY, per BCP 14). Guardrails come first — plan before you build, keep context clean, never delete, always leave an audit trail.

## What's inside

| Part | What it covers |
|------|----------------|
| **Specification** | The core RFC-style chapters: input paths, the five-step pipeline, memo strategies, revisions, phases & PRDs, rollout, orchestration, git & security. |

| **Prompt generator** | The validated engine that turns memo structure into agent prompts. |
